02SketchMind

Supporting algorithmic reasoning through executable sketching

// Slide 3. Four beats: (b), (c), (d), then the repair arrow. SketchMind turns learners' sketches into executable plans, with four features. (a) Executable tracing: every pen stroke runs an operation and becomes a trace step. [1] (b) Reusable pens: merge steps into your own pen, like compare_and_swap. [2] (c) Multi-level views: the same trace as values, positions, and parameters. [3] (d) Counterexamples: when she's done, SketchMind finds an input where her plan fails. [4] And she repairs it, turning her steps into a loop. Let's see each one in the real system.

// Slide 9. Twenty-one beats; keep each line short. For an audience new to SMT. How is that counterexample found? An SMT solver finds numbers that satisfy a set of facts, or proves none exist. Her input is a0 to a3. [1] We run naive Bubble Sort next to her plan. She is missing passes 2 and 3. [2] Each step gives a fact: a0 > a1… [3] …a0 ≤ a2… [4] …a2 > a3. [5] Pass 2: a1 ≤ a0… [6] …and a0 ≤ a3. [7] Pass 3: a1 ≤ a0. [8] She does pass 1, so we keep those facts. [9] For the passes she skips, we flip facts… [10] …one by one… [11] …to ask for an input where Bubble Sort does a step she doesn't. [12] This flip clashes with a kept fact. [13] So does this one. [14] Only a0 > a3 works: pass 2 must swap, and pass 2 is what she's missing. [15] In the solver's language: four unknowns and these facts. [16] Goals: fewest changes, then smallest L1 distance, then smaller numbers. [17] Check. [18] One change gives three candidates. [19] L1 drops one. [20] The smaller sum wins: 3, 1, 7, 2. [21] Her steps on it: not sorted. That's the counterexample.
03Implementation

Three layers, one loop.

// Slide 14. Three beats. Briefly, the implementation: three layers in one loop. The sketch layer turns handwriting into an array and strokes into operations. Gemini recognizes the digits; for a stroke, what counts is which elements it crosses, not its shape. [1] The execution engine keeps a versioned sequence of steps and replays them, with her own ink. [2] The symbolic engine compiles her trace to SMT-LIB and checks it with Z3. [3] If her plan is correct, she's done. If not, the counterexample comes back as a new instance, and she replays her sketch on it.

06Discussion

Discussion

Is the nearest counterexample the clearest one?
The solver minimizes the change. But the closest failing input may not make the misconception most apparent. Instructors asked for local cues too, e.g. highlighting one operation group.
Sketch first, code later?
Participants suggested a staged pipeline with platforms like “LeetCode”: validate the logic as a sketch, then pay the syntax cost in an IDE.
What would Dijkstra need?
A graph state, distance labels, visited marks, and new primitive pens:
ExtractMinMarkVisitedRelaxEdge+ new SMT predicates
possible design how these pens could run Dijkstra.
Learners already have a visual language.
Learners drew bubbles sized by value, bars, circles, or numbers. Can SketchMind support this expressiveness?
beta Abstract pen: draw anything, then give it a value.
