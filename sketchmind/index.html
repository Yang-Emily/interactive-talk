01Motivation
C1Trace explosion
Intermediate states pile up. Redrawing is tedious and error-prone, so people skip steps.
C2The abstraction leap
Steps stay tied to concrete values. It's hard to see a repeated compare-and-swap as an inner loop.
C3Instance overfitting
A "happy path" example passes. Test cases say that it fails, not why, and they look nothing like the learner's example.
// Three beats; each plays the part of the hand-drawn clip where that challenge's label appears (sped up 1.5×). [1] C1, trace explosion. As the process continues, her page fills with rewritten arrays. To cope, she starts skipping steps or compressing operations, and mistakes go unnoticed: here a drawing error, then skipped steps. [2] C2, the abstraction leap. She senses she is repeating the same actions, but she struggles to describe the pattern. The page is rows of numbers without structure. [3] C3, instance overfitting. After one pass, the array may look sorted, so she concludes Bubble Sort only needs one pass. That conclusion rests on a single example and does not generalize.

02SketchMind

Supporting algorithmic reasoning through executable sketching

aExecutable tracing
bReusable pens
cMulti-level trace views
dCounterexamples
In this context, we present SketchMind, which helps users externalize, execute, and check their understanding of a given algorithm. It has four capabilities: (a) executable tracing, (b) reusable pens, (c) multi-level trace views, and (d) counterexample generation. Let's follow Alice through each of them on the real system.
aExecutable tracing
live · SketchMind

Pen strokes become executable operations.

Back in SketchMind: Alice’s array [3, 1, 7, 4], about to be sketched.

Data pen: 3 1 7 4 is recognized as an array.

Compare 3 and 1 → is_bigger(3, 1) = True.

Swap them: the numbers move; nothing is redrawn.

Compare 3 and 7 (False), then 7 and 4 (True).

Swap 7 and 4 → [1, 3, 4, 7]. Looks sorted.

// Five beats. This is the real SketchMind app (iframe), driven by a script: every stroke is a pointer event on its canvas. Now in SketchMind. Alice starts again, with A = [3, 1, 7, 4]. [1] Alice sketches an array on the canvas, and the system recognizes it as an array. [2] She selects the compare tool and marks two numbers. The result appears on the right-hand panel: 3 is greater than 1. [3] She then uses the swap tool to exchange them. The numbers move; nothing is redrawn. [4] She continues with 3 and 7, and 7 and 4. Any stroke shape works; what matters is which numbers it crosses. [5] Swap 7 and 4: [1, 3, 4, 7]. SketchMind keeps a clear, replayable record of her reasoning. That addresses C1.

// Three beats: the second pass that the counterexample requires. To show that the previous example does not complete all required passes, we generate a counterexample with two properties. First, all of the student's earlier steps remain valid: every comparison comes out the same way, so the replay follows Alice's path. Second, the new example requires additional steps to finish: after replay, it is not sorted. Among such inputs we take the one closest to the original. This helps reduce student confusion while still exposing the mistake. We use a logic solver, Z3, to construct this counterexample. live · SketchMind

02Implementation

Three layers

Sketch layer
  • Data pen: handwritten digits → array slots
  • Operation pens: the pen picks the operation, the stroke picks the elements
  • Gestures: merge / split cards
Gemini 3.0 Flash · digit recognition
Execution engine
  • Versioned step sequence
  • Insert / delete → downstream recompute
  • Multi-instance replay with original ink
React · TypeScript
Symbolic engine
  • Compile trace → SMT-LIB
  • Check correctness
  • Find the closest failing input
Z3
↩ the counterexample comes back as a new instance to replay
// Static. Keep it short. Briefly, the implementation. The sketch layer recognizes handwritten digits and maps strokes to operations. Stroke shape doesn't matter; what counts is which elements the stroke crosses. The execution engine keeps a versioned sequence of steps and replays them across instances. The symbolic engine compiles the trace to SMT, and the counterexample it finds is added back as a new instance the learner can practice on.
02Beyond Bubble Sort

Pancake Sort: new primitives, same workflow.

Customized primitives: find_max and flip.

find_max on [2, 4, 1, 3], flip the 4 to the front, flip it to the end.

The steps merge into flip_max_to_front / flip_max_to_end pens.

Applied round by round → [1, 2, 3, 4].

Merged into a pancake_sort pen. Done → array sorted.

// Four beats; recording sped up 1.25×. More generally, SketchMind can be extended to other algorithms by defining customized primitives. [1] For example, we explore Pancake Sort using primitives such as findMax, which locates the maximum element, and flip, which reverses a range. [2] As with Bubble Sort, the learner merges these steps into reusable pens. [3] Applying them round by round sorts the stack. [4] Finally the rounds become one pancake_sort procedure, and the check passes.

We ran a preliminary study with 20 participants: 15 students and 5 instructors, in person on an iPad with a pencil. Stage one used bubble sort, which everyone knew, with four guided tasks that each introduced one feature. Stage two used pancake sort, which nobody knew, not even the instructors. Participants built their own solution while thinking aloud. In both stages they sketched on paper first, which gave us the paper sketches you saw earlier. Finally, a survey and an interview.

04Discussion

Toward a general SketchMind

reused across algorithmscanvas · trace · replay · pen composition · counterexample pipeline
per algorithmprimitive pens · visual model · views · SMT predicates
  • Bubble → Pancake reused the infrastructure; it added range selection, find_max and flip.
  • Learners' own visual language (bars, circles, bubbles) is a cue we don't use yet.

Limitations

  • Proof of concept: two array-based sorting algorithms with local, sequential operations.
  • Learners compose pens, but cannot define new primitives.
  • The minimal change is not always the most instructive one.
  • We measured usability, not learning outcomes. No transfer, retention, or control group.
// Two beats. What would a general SketchMind take? The canvas, the trace, replay, composition, and the counterexample search carry over between algorithms. Going from bubble to pancake reused all of them. What's specific to each algorithm are the primitive pens, the visual model, the views, and the SMT predicates. [1] Participants also drew bars, circles, and bubbles. A future system could interpret that visual language. [2] Limitations: this is a proof of concept for two sorting algorithms. Learners can't define new primitives. The smallest change isn't always the most instructive one. And we studied usability, not learning gains.

// Optional. Drop this slide if time is short. One question we often get: why not just ask an LLM? We're testing that now. On 50 bubble sort cases, recent models like Gemini 3.8 Flash and GPT-5.5 found valid counterexamples every time, but took 15 to 20 seconds each.
